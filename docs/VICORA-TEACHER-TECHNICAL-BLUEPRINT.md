# VICORA TEACHER — Technical Blueprint

## Product scope
VICORA TEACHER is a separate teaching and academic-document workspace for Nigerian Primary 1–6, JSS 1–3 and SS 1–3. It is a companion module in the VICORA product family. It does not replace or modify VICORA Practice.

## Confirmed product decisions
- Product name: VICORA TEACHER
- Audience: Primary, Junior Secondary and Senior Secondary
- Teacher accounts: separate registration and sign-in
- Storage: central Google Drive, organised by school
- Structured data: a dedicated Google Sheets database
- Backend: a dedicated Google Apps Script project
- Frontend: responsive static web application using the VICORA Practice design language
- Output: print-ready PDF through browser print and editable DOCX
- AI: same provider set, model IDs, routing and fallback strategy as VICORA Public Practice

## Repository isolation
Development is isolated on branch `vicora-teacher-foundation` in the VICORA Public Practice repository, under new paths only:
- `public/teacher/`
- `api/teacher/`
- `teacher-backend/`
- `docs/`

No existing VICORA Practice file is changed on this branch. The branch is not merged or deployed to production as part of this work.

## Architecture
1. Browser UI at `/teacher/`.
2. Vercel serverless proxy at `/api/teacher/*`; the browser never receives the Apps Script URL or AI API keys.
3. Dedicated Teacher Apps Script deployment, configured as `VICORA_TEACHER_APPS_SCRIPT_URL` in the Teacher Vercel project.
4. Dedicated Google Sheets database with tenant-aware rows.
5. Central Google Drive folder with school-specific subfolders and a global curriculum folder.
6. AI provider router copied as a compatible implementation of VICORA Practice's provider order/model configuration. Apps Script projects have isolated Script Properties, so API keys and provider order must be configured in the Teacher backend separately unless a future shared AI gateway is deliberately introduced.

## Roles
- Platform Admin: all schools, global resources, provider settings, platform-level administration.
- School Admin: own school, teacher membership, school resources and templates.
- Teacher: own documents and resources permitted to the school.

The first user who creates a school workspace becomes its School Admin. A teacher joining an existing school must use its school join code. Platform Admin access is bootstrapped with a one-time key generated by the setup function.

## Nigerian academic conventions
The app supports:
- Primary 1–6, JSS 1–3 and SS 1–3.
- First, Second and Third Term.
- Lesson note formats configurable by level and school.
- Objective, theory/essay, structured, short-answer, fill-in and matching assessments.
- Schemes of work organised by week, topic, subtopic, objectives, activities, resources and assessment.
- Curriculum-aligned generation using uploaded references.
- Nigerian English, Naira formatting where relevant, and age-appropriate language.

Curriculum claims must be traceable to an uploaded reference or clearly marked as an AI suggestion. The app must not claim that an AI-generated document is officially approved.

## Data model
Dedicated sheets:
- TeacherUsers
- TeacherSessions
- TeacherSchools
- TeacherDocuments
- TeacherResources
- TeacherTemplates
- TeacherAIUsage
- TeacherPasswordResets
- TeacherAuditLogs

Every school-owned record includes a school ID. Every teacher-owned document includes a user ID. All read/write operations enforce ownership and school membership in Apps Script.

## Document workflow
1. Teacher selects document type, level, class, subject, term/week and topic.
2. Backend finds relevant reference passages from global and school resources.
3. AI generates structured academic content using the selected Nigerian format.
4. Output is saved as a versioned document record.
5. Teacher edits the document in the workspace.
6. PDF is printed from the A4 print stylesheet; DOCX is generated as a real Office Open XML document.
7. Saved documents can be reopened, edited, duplicated and deleted by their owner or authorised school admin.

## Resource upload and retrieval
- Admins upload PDF, DOCX, TXT and supported reference files.
- Browser extracts text from PDF/DOCX before upload; original files are retained in Drive.
- Extracted text is indexed in the database/resource text file and retrieved by keyword relevance.
- Global resources are visible to all schools; school resources are visible only to that school.
- Upload size and extracted text length are capped to protect Apps Script quotas and Sheets limits.
- Files are private by default; never expose unrestricted public Drive links.

## AI provider configuration
Compatible provider IDs and default model IDs are copied from the existing Practice AI router. The Teacher deployment stores its own keys and provider order in its own Script Properties. This avoids changing or coupling the live Practice backend. Provider keys remain server-side only.

## Security and reliability
- Passwords are salted and SHA-256 hashed; sessions store token hashes, not raw tokens.
- Use Apps Script LockService around registration and writes.
- Validate all fields and enforce role/tenant ownership on every endpoint.
- Keep AI keys and admin bootstrap key out of GitHub and browser code.
- Record audit events for admin actions and AI usage.
- Use soft deletion/status fields for important records.
- Never put student-sensitive information in prompts unless necessary and authorised.
- Do not use real student names in demo/test data.

## Deployment
1. Create a dedicated Apps Script project named VICORA TEACHER Backend.
2. Copy `teacher-backend/Code.gs` and manifest.
3. Run `setupVICORATeacher` once and securely store the one-time Platform Admin key.
4. Deploy as Web App, execute as owner, access Anyone.
5. Create a separate Vercel project for this branch/root deployment and set `VICORA_TEACHER_APPS_SCRIPT_URL`.
6. Do not change the existing VICORA Practice project environment variables or deployment.
7. Test registration, tenant isolation, document generation, resource upload, PDF printing and DOCX export before launch.

## Delivery sequence
- Milestone 1: isolated foundation, authentication, tenant-aware database and shared-style dashboard.
- Milestone 2: lesson note generator and print/DOCX output.
- Milestone 3: examination/test generator, question bank and marking guides.
- Milestone 4: scheme of work and syllabus assistant.
- Milestone 5: reference library, curriculum retrieval and document assistant.
- Milestone 6: reports, templates, admin controls, security and deployment testing.

## Known constraint
The existing Practice Apps Script and Teacher Apps Script are separate projects. Their Script Properties cannot be read across projects. This first implementation mirrors the Practice provider router and model IDs, while keeping Teacher API keys and settings separate. A truly central AI settings panel would require an explicitly approved shared AI gateway integration.
